# nagara — ずっと声を流し続けてくれるツール 設計ドキュメント

自宅で「なんとなく耳を傾けていたら意味がある」距離感で、声を流し続けるツール。
内部コードネームは **nagara**（ながら聴き）。

このディレクトリは設計ドキュメントだけを置いている。実装は別ディレクトリに切り出す前提。

## 一行サマリ

- **コア体験は「URL 1 本貼るだけでキューに積める、プラットフォーム横断の手動キュー」**。
  メインプレイヤー UI と、スマホからさっと積める軽量な補助 UI の 2 系統を用意し、
  WebSocket でリアルタイムに同期する。
- **再生は 3 つの Tier から自動選択**（ながら聞きを破綻させないために、
  エピソード切替に人間操作を要求しない設計）:
  - Tier 1: ネイティブ埋め込み（YouTube IFrame Player API、`<audio>`）
  - Tier 2: yt-dlp で m3u8 を解決し、バックエンドの HLS プロキシ経由で `hls.js` 再生（DRM 無し限定）
  - Tier 3: 専用の Chrome 拡張が別タブを自動制御し、`ended` を本体に通知（TVer 等の DRM サイト用）
- **「今すぐ割り込みで見る」操作**: 再生中の動画は再生位置を保持して一時停止し、
  割り込みアイテムを見終えると元の位置から自動復帰する（スタック型）。
- ローカルネットワーク内の Linux PC で systemd 常駐させる構成を第一候補とする。
  バックエンドは **Go（単一バイナリ）＋ SQLite**、フロントは **Vite + React + TypeScript**。

## このドキュメントのスタンス

- 最初に分厚い設計を固めるのではなく、**ミニマムに作って触ってから本設計に落とす**方針。
- そのため「MVP で必ず作るもの」と「MVP では作らないが将来検討するもの」を明確に分ける。
- 各サービス（YouTube／Podcast／TVer 等）の実現可能性は、想像ではなく公式仕様または
  既存実装の挙動を確認した上で記述する（出典は [02-research.md](./02-research.md)）。
