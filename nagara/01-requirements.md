# 01. 要求整理

Issue #32 本文・コメント、本タスク依頼文、および本タスクの追加フィードバックから
要求を整理する。

## 0. 設計の出発点（重要）

依頼文と追加フィードバックから読み取れる **本ツールの第一歩目の課題** は以下である:

> 普段からやっている「次これ見よう」を、**プラットフォームをまたいで** 1 本のキューに積み、
> **YouTube の使いづらいキューに縛られず** に順次消化したい。

つまり、自動キューイング（チャンネル登録・新着取得・おすすめ生成）よりも先に、
**「URL を貼ってキューに積み、頭から流すだけ」の手動キュー** を最初に作る。
これが固まらないうちに自動化を作っても、「自動で積まれたものが結局見たくない」状態が出るだけで
中途半端になる――という判断（タスク追加フィードバックで明示されたもの）。

## 0-2. 「ながら聞き」コンセプトの定義（守らないと設計が破綻する制約）

本ツールはコンセプト名のとおり「**ながら聞き**」を成立させるためのツールである。
ながら聞きを定義として書き下すと、以下の **必達条件** を満たすことを意味する:

1. **ユーザーが画面の前にいない／画面を見ていない時間帯が大半である** ことを前提にする。
2. **エピソードの切り替わりに人間の操作を要求してはならない**。流し始めたら、エピソード末尾で
   勝手に次へ進み、何時間でも声が流れ続ける状態が維持される必要がある。
3. ユーザー操作が必要なのは「セッション開始時の最初の 1 アクション」「キューの編集」「ザッピング時の
   『続けるか／切るか』のような明示的な意思決定」のみ。

この定義から導かれる重要な含意:

- **「外部タブを開いて人間がそこで再生し、人間が見終わったら『次へ』を押す」運用は本コンセプトを破綻させる**。
  画面の前にいないという前提と矛盾するため、本ツールの一次的な再生手段としては採用できない。
- 「埋め込みできないからリンクとして並べておく」程度の解は、本ツールの存在意義そのものを打ち消す。
  したがって、各プラットフォームについては
  「**どうすればアプリ内で／自動進行可能な形で再生できるか**」を埋め込み拒否のときも検討する義務がある。

> 前バージョンの設計（コミット `1fd1347`）はこの含意を見落とし、
> TVer 等を「外部タブ＋手動進行」で扱っていた。本タスクの追加フィードバックで指摘されて修正する。

## 1. ユーザーストーリ

- 起きている時間に、自室で、自分（=作者）が
- 音楽でも「ちゃんと見たい動画」でもなく、選ぶ手間ゼロで、
- なんとなく耳を傾けると意味がある、くらいの距離感の声を
- 流し続けてほしい。
- ただし、何を流すかは自分の **「次これ見よう」** に従う（自動推薦は当面不要）。
- 流す対象は YouTube／Podcast／TVer など **プラットフォームをまたぐ**。

## 2. 利用環境（前提条件）

| 項目 | 前提 |
|---|---|
| 視聴端末 | 自宅の Windows PC（メイン） |
| 動かす場所 | 同 LAN 上の Linux PC でも、視聴用 Windows PC でも可 |
| ネットワーク | LAN 内に閉じてよい。インターネット越しの公開は不要 |
| 起動運用 | 「起動が面倒」は嫌。Linux 常駐なら起動の手間が消えるのでむしろ歓迎 |

→ 「Linux PC で常駐」を第一候補、「Windows 単体」を退避ルートとする
（理由は [03-mvp-design.md](./03-mvp-design.md#デプロイ戦略) で述べる）。

## 3. 機能要求

### 3-1. キューの中心機能（MVP の核）

- **URL を 1 本貼るだけでキュー末尾に追加** できる。
  - 対応プラットフォームは URL から自動判定する（[02-research.md](./02-research.md)§URL 判定）。
- 追加された行はメタデータ（タイトル・投稿者・サムネ・長さ）が自動で埋まる。
- キューの操作:
  - 並び替え（次に再生したいものを上に）
  - 削除
  - 「次これ再生」（先頭に挿入）
  - 「いま再生中をスキップ」
- キューの永続化: ブラウザを閉じてもキューが残る（サーバー側 SQLite に保持）。

### 3-2. 再生コントロール（プラットフォーム横断）

各エピソードを **統一された操作インターフェイス** で扱う。
プラットフォームごとに使える再生経路は §3-2-2 の Tier 階層で選ぶ。

| 操作 | YouTube | 音声直リン／Podcast | yt-dlp 抽出 → hls.js | Chrome 拡張モード |
|---|---|---|---|---|
| ロード | iframe Player API で `cueVideoById` | `<audio src>` 設定 | バックエンドが m3u8 解決 → `Hls.loadSource` | 拡張に「これを開いて再生」を依頼 |
| 再生 | `playVideo()` | `audio.play()` | `video.play()` | 拡張がタブを操作 |
| 一時停止 | `pauseVideo()` | `audio.pause()` | `video.pause()` | 拡張へ pause メッセージ |
| 見終わり検知 | `onStateChange` で ENDED | `ended` イベント | `<video>` の `ended` イベント | 拡張のコンテンツスクリプトで `ended` を捕捉して本体へ通知 |
| 再生速度 | `setPlaybackRate` | `playbackRate` | `playbackRate` | 拡張がタブ内で `playbackRate` を設定 |
| フルスクリーン | コンテナ `requestFullscreen` | （該当なし） | コンテナ `requestFullscreen` | 拡張が新規タブをアクティブ化 |

### 3-2-2. 再生経路の Tier 階層（必達原則）

「ながら聞き」を破綻させないため、各プラットフォームについて以下の **Tier 階層** で
再生経路を選択する。**Tier 1〜3 のいずれかが成立しないプラットフォームは、原則として MVP の対応対象から外す**
（外部タブ手動進行に落とすぐらいなら、初期は対象外にして後で Tier 2/3 を整備する）。

| Tier | 経路 | コンセプト整合性 |
|---|---|---|
| **Tier 1: ネイティブ埋め込み** | YouTube IFrame Player API、`<audio>`、その他公式埋め込み iframe | 完全自動 |
| **Tier 2: yt-dlp 抽出 + アプリ内再生** | バックエンドで yt-dlp が m3u8 等を解決 → フロントが `hls.js` で再生（DRM 無し限定） | 完全自動 |
| **Tier 3: Chrome 拡張モード** | nagara 専用 Chrome 拡張をユーザーがインストール。タブを拡張が制御し、コンテンツスクリプトで `ended` 検知して本体に通知 | 拡張インストール後は完全自動。Tier 2 で抜けない DRM 動画もカバーできる |
| **Tier 4: 外部タブ手動進行** | ブラウザ標準の新規タブで開いてユーザーが見終わりに「次へ」を押す | **コンセプト破綻**。MVP では採用しない。最終手段としても基本的に避ける |

実装方針:

- 各プラットフォームの URL を貼った時点で、対応している最上位の Tier を自動選択する。
- Tier 1 で失敗（YouTube `onError` 101/150 等）したら自動で Tier 2 → Tier 3 にフォールバックする。
- Tier 3（拡張モード）は **拡張をインストールしているユーザーのみ有効化** する。
  拡張未インストールのときは Tier 2 までで再生できなかったら、そのアイテムは「再生不可」として扱う
  （キューには残せるが自動再生時はスキップ）。

### 3-2-3. プラットフォームごとの最低達成 Tier（MVP 受け入れ条件）

| プラットフォーム | MVP で必達 Tier | 備考 |
|---|---|---|
| YouTube（埋め込み許可動画） | Tier 1 | IFrame Player API |
| YouTube（埋め込み拒否動画） | Tier 2（拡張有効時は Tier 3 でも可） | yt-dlp で m3u8 抽出 |
| Podcast（mp3 / m4a / RSS） | Tier 1 | `<audio>` 直 |
| 任意 mp3 / m4a 直リン | Tier 1 | `<audio>` 直 |
| TVer | **Tier 3 必須**（拡張インストール前提） | DRM（Widevine）採用のため Tier 2 不可。アプリ内再生は不可能なので、拡張がタブを管理して `ended` を検知する |
| Radiko | Tier 2 | auth1/auth2 → HLS のためバックエンドプロキシ経由。優先度は中（[04-roadmap.md](./04-roadmap.md)） |
| その他 yt-dlp 対応サイト（1000+） | Tier 2 | DRM 無しなら自動的に対応する |

→ つまり MVP には **Tier 1（YouTube／音声）＋ Tier 2（yt-dlp）＋ Tier 3（拡張モード、TVer 等用）**
が同居する。これで「ながら聞き」を破綻させずにプラットフォーム横断を実現する。

### 3-3. 視聴履歴

- キューから消えた行は履歴として残る（`completed` / `skipped`）。
- 同じ URL を再投入することは可能（履歴を見て再度キューに入れたい時のため）。
- 自動的な「重複再生抑制」は **MVP では弱め** にする
  （手動キューに自分で積んだ以上、流すのは尊重する）。

### 3-4. ザッピング機能

- 「数分で自動で次へ」「途中で『続き見る？』を出す」――この体験は本ツールの根本機能なので
  キュー中心になっても残す。
- ただしデフォルトは **長め**（例: 60 分）または OFF にして、
  「自分で積んだ動画を強制スキップしてしまう」事故を避ける（フィードバックの意図に沿う）。

### 3-5. その他リクエスト

- 任意の User-Agent を指定（コメント由来）。
  → サーバーから外部メタ取得（oEmbed・og:タグ・Podcast RSS 等）するときに使う環境変数として扱う。

### 3-6. 自動キューイング（=チャンネル登録・新着取得）

- **MVP に入れない**（タスクフィードバックで明示）。
- 「投稿者ごとに『全部連続して見たい』わけではない」ため、
  自動化のロジック（何を入れる・何を入れない）が確定しないまま自動化を作るのは中途半端。
- まず手動キューで運用し、「どういう自動化が必要か」を運用の中で見極めてからロードマップで実装する。

## 4. 非機能要件

### 4-1. ネットワーク

- LAN 内アクセス前提。認証は MVP では不要。
- インターネットに公開しない。

### 4-2. 運用

- 「起動が面倒」を避けるのが最優先要件のひとつ。
  - Linux 常駐 → systemd で起動する想定。
  - Docker は採用しない（ミニマムに対して重い）。

### 4-3. データ保持

- キュー・履歴・設定はローカル SQLite ファイルに永続化。
- 単一ユーザー想定。

### 4-4. データの整合性

- キューの並び（position）と「いま再生中」（status='playing'）の整合性を担保する必要がある。
  - 「2 タブで開いて両方再生」のようなケースは想定外（注意書きで運用回避）。
  - サーバー側のキュー操作は単純な SQL で済むようテーブル設計する（[03-mvp-design.md](./03-mvp-design.md)）。

## 5. スコープ管理（MVP の境界）

| 項目 | MVP に入れる？ | 補足 |
|---|---|---|
| URL 1 本でキューに追加 | ○ | コア体験 |
| Tier 1: YouTube IFrame Player API 再生 | ○ | oEmbed でメタ取得 |
| Tier 1: 音声直リン（.mp3 / .m4a 等）の `<audio>` 再生 | ○ | Podcast の `<enclosure>` URL もこの経路 |
| Tier 2: yt-dlp 抽出 → hls.js でアプリ内再生 | ○ | YouTube 埋め込み拒否動画／その他 yt-dlp 対応サイト |
| Tier 3: Chrome 拡張モード（拡張インストール時のみ） | ○ | TVer 等 DRM つきプラットフォーム用。**拡張本体は MVP の成果物に含む** |
| Podcast RSS の URL を貼る → エピソードを選んで追加 | △ | RSS 単発取得＋一覧 UI が要るのでサブセットでスタート |
| キューの並び替え・削除・先頭挿入 | ○ | |
| 履歴（completed/skipped）保持 | ○ | |
| ザッピング（タイマーで次へ＋続き確認） | ○ | デフォルトは緩めの設定 |
| 再生速度コントロール | ○ | Tier 1〜3 で動作 |
| フルスクリーン | ○ | Tier 1（YouTube）／ Tier 2（hls.js の `<video>`） |
| コメントスクリーン付きフルスクリーン | × | コメント取得元未定 |
| チャンネル登録・新着 RSS クロール | × | ロードマップ |
| おすすめ／自動キュー生成 | × | ロードマップ |
| 正規表現フィルタ・ミュートリスト | × | チャンネル登録が無いと使い所が薄い |
| Radiko 連携 | × | 認証フロー実装が重い |
| 任意 UA 設定 | △ | 環境変数で 1 個だけ提供（yt-dlp と og:タグ取得に渡す） |
| スマホ対応 | × | Windows ブラウザのみ |
| 認証 | × | LAN 限定 |
| **外部タブ手動進行（旧 ExternalLinkAdapter）** | × | コンセプト破綻のため MVP からは削除 |

> △は「最小サブセットだけ MVP に入れる／環境変数のみで提供」の意。
