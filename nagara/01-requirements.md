# 01. 要求整理

本ツールが満たすべき要求と非機能要件をここで定義する。

## 1. プロダクトの位置づけ

> **普段からやっている「次これ見よう」を、プラットフォームをまたいで 1 本のキューに積み、
> YouTube の使いづらいキューに縛られずに順次消化したい。**

これが第一歩目の課題であり、本ツールはこの課題への解として **手動キュー中心** で組む。
チャンネル登録・自動クロール・おすすめキューイングといった自動化は、
**この手動キュー体験が固まった後に** 必要性を見極めて足していく。

## 2. 「ながら聞き」コンセプトの定義（破綻させない制約）

本ツールはコードネームのとおり「**ながら聞き**」を成立させるためのものである。
ながら聞きを定義として書き下すと、以下の**必達条件**を満たすことを意味する:

1. **ユーザーが画面の前にいない／画面を見ていない時間帯が大半である**ことを前提にする。
2. **エピソードの切り替わりに人間の操作を要求してはならない**。流し始めたら、
   エピソード末尾で勝手に次へ進み、何時間でも声が流れ続ける状態が維持される。
3. ユーザー操作が必要なのは「セッション開始時の最初の 1 アクション」「キューの編集」
   「割り込み再生のような明示的な意思決定」のみ。

この定義から導かれる重要な含意:

- **「外部タブを開いて人間がそこで再生し、人間が見終わったら『次へ』を押す」運用は採用しない**。
  画面の前にいないという前提と矛盾するため、本ツールの再生手段としては成立しない。
- 各プラットフォームについて「**どうすればアプリ内で／自動進行可能な形で再生できるか**」を
  埋め込み拒否のときも検討する。具体的な経路は §3-2-2 の Tier 階層で定義する。

## 3. 利用環境（前提条件）

| 項目 | 前提 |
|---|---|
| 視聴端末 | 自宅の Windows PC（メイン） |
| 補助操作端末 | スマートフォン（補助 UI からの追加用） |
| 動かす場所 | 同 LAN 上の Linux PC で常駐 |
| ネットワーク | LAN 内に閉じてよい。インターネット越しの公開は不要 |
| 起動運用 | 「起動が面倒」は嫌。systemd で常駐させて起動の手間を消す |

→ デプロイ構成の詳細は [03-mvp-design.md](./03-mvp-design.md#デプロイ戦略) を参照。

## 4. 機能要求

### 4-1. キューの中心機能（MVP の核）

- **URL を 1 本貼るだけでキュー末尾に追加** できる。
  - 対応プラットフォームは URL から自動判定する。
- 追加された行はメタデータ（タイトル・投稿者・サムネ・長さ）が自動で埋まる。
- キューの操作:
  - 並び替え（次に再生したいものを上に）
  - 削除
  - 「次に再生」（先頭に挿入）
  - 「**今すぐ割り込みで見る**」（後述 §4-2）
  - 「いま再生中をスキップ」
- キューの永続化: ブラウザを閉じてもキューが残る（サーバー側 SQLite に保持）。

### 4-2. 割り込み再生（スタック復帰）

- 任意のキュー操作画面・補助 UI から「**今すぐ割り込みで見る**」を実行できる。
- 動作:
  1. いま再生中のアイテムを **一時停止し、再生位置（秒）を保存** する。
  2. 割り込みアイテムを即座に再生開始する。
  3. 割り込みアイテムが終わったら、**元のアイテムを保存した再生位置から自動復帰** する。
- 割り込みの中で更に割り込みが可能（スタック型）。最も奥のものから順に復帰していく。
- 元のキュー順序は変わらない（割り込みアイテムは通常キューの位置を取らない）。

### 4-3. 再生コントロール（プラットフォーム横断）

各エピソードを **統一された操作インターフェイス** で扱う。
プラットフォームごとに使える再生経路は §4-3-2 の Tier 階層で選ぶ。

| 操作 | Tier 1（ネイティブ埋め込み） | Tier 2（yt-dlp + hls.js） | Tier 3（Chrome 拡張モード） |
|---|---|---|---|
| ロード | iframe Player API で `cueVideoById` / `<audio src>` 設定 | バックエンドが m3u8 解決 → `Hls.loadSource` | 拡張に「これを開いて再生」を依頼 |
| 再生 | `playVideo()` / `audio.play()` | `video.play()` | 拡張がタブを操作 |
| 一時停止 | `pauseVideo()` / `audio.pause()` | `video.pause()` | 拡張へ pause メッセージ |
| 見終わり検知 | `onStateChange` で ENDED / `ended` イベント | `<video>` の `ended` イベント | 拡張のコンテンツスクリプトで `ended` を捕捉して本体へ通知 |
| 再生速度 | `setPlaybackRate` / `playbackRate` | `playbackRate` | 拡張がタブ内で `playbackRate` を設定 |
| シーク復帰（割り込み戻り用） | `seekTo(seconds)` / `currentTime = ...` | `video.currentTime = ...` | 拡張がタブ内 `<video>.currentTime` を設定 |
| フルスクリーン | コンテナ `requestFullscreen` | コンテナ `requestFullscreen` | 拡張が新規タブをアクティブ化 |

### 4-3-2. 再生経路の Tier 階層

「ながら聞き」を破綻させないため、各プラットフォームについて以下の **Tier 階層** で
再生経路を選択する。**Tier 1〜3 のいずれかが成立しないプラットフォームは MVP の対応対象から外す**。

| Tier | 経路 | コンセプト整合性 |
|---|---|---|
| **Tier 1: ネイティブ埋め込み** | YouTube IFrame Player API、`<audio>`、その他公式埋め込み iframe | 完全自動 |
| **Tier 2: yt-dlp 抽出 + アプリ内再生** | バックエンドで yt-dlp が m3u8 等を解決 → フロントが `hls.js` で再生（DRM 無し限定） | 完全自動 |
| **Tier 3: Chrome 拡張モード** | nagara 専用 Chrome 拡張をユーザーがインストール。タブを拡張が制御し、コンテンツスクリプトで `ended` 検知して本体に通知 | 拡張インストール後は完全自動。Tier 2 で抜けない DRM 動画もカバーできる |

実装方針:

- 各プラットフォームの URL を貼った時点で、対応している最上位の Tier を自動選択する。
- Tier 1 で失敗（YouTube `onError` 101/150 等）したら自動で Tier 2 → Tier 3 にフォールバックする。
- Tier 3（拡張モード）は **拡張をインストールしているユーザーのみ有効化** する。
  拡張未インストールのときは Tier 2 までで再生できなかったら、そのアイテムは「再生不可」として扱う
  （キューには残せるが自動再生時はスキップ）。

### 4-3-3. プラットフォームごとの最低達成 Tier（MVP 受け入れ条件）

| プラットフォーム | MVP で必達 Tier | 備考 |
|---|---|---|
| YouTube（埋め込み許可動画） | Tier 1 | IFrame Player API |
| YouTube（埋め込み拒否動画） | Tier 2（拡張有効時は Tier 3 でも可） | yt-dlp で m3u8 抽出 |
| Podcast（mp3 / m4a / RSS） | Tier 1 | `<audio>` 直 |
| 任意 mp3 / m4a 直リン | Tier 1 | `<audio>` 直 |
| TVer | **Tier 3 必須**（拡張インストール前提） | DRM（Widevine）採用のため Tier 2 不可。拡張がタブを管理して `ended` を検知する |
| その他 yt-dlp 対応サイト（1000+） | Tier 2 | DRM 無しなら自動的に対応する |

### 4-4. 視聴履歴

- キューから消えたアイテムは履歴として残る（`completed` / `skipped`）。
- 同じ URL を再投入することは可能（履歴を見て再度キューに入れたい用途）。

### 4-5. 補助 UI（軽量・スマホ前提）

メインプレイヤー UI とは別に、**「URL をさっとキューに入れるだけ」の軽量な追加 UI** を提供する。

- スマホブラウザで快適に開けるサイズ・操作性。
- 操作は実質 3 種類だけ:
  - **キュー末尾に追加**
  - **次に再生（先頭に挿入）**
  - **今すぐ割り込みで見る**
- 共有メニュー（OS のシェア）から呼べる導線を考慮する（PWA 化／URL クエリで初期値）。
- メインプレイヤー UI を開いている別端末には、追加操作が **WebSocket 経由でリアルタイムに反映** される
  （後述 §4-6）。

### 4-6. メイン UI のリアルタイム反映（WebSocket）

メインプレイヤー UI は以下の状態変化を **WebSocket 経由で push 受信** し、再描画する:

- キュー内容の変更（追加・削除・並び替え・割り込み挿入・割り込み復帰）
- 個別アイテムのメタデータ取得完了（タイトル・サムネ等が後から埋まる）
- 再生中アイテムの切替（自動進行・割り込み開始・割り込み復帰）
- ストリーム解決（Tier 2 の m3u8 解決完了・失敗による Tier 降格）

これにより、補助 UI で追加した瞬間にメイン側のキュー末尾に新行が現れたり、
拡張側からの `ended` 通知でメイン UI の表示が即時更新されたりする。

### 4-7. その他リクエスト

- 任意の User-Agent を指定（サーバが外部メタ取得・yt-dlp 実行時に渡す UA）。

## 5. 非機能要件

### 5-1. ネットワーク

- LAN 内アクセス前提。認証は MVP では不要。
- インターネットに公開しない。

### 5-2. 運用

- 「起動が面倒」を避けるのが最優先要件のひとつ。
  - Linux 常駐 → systemd で起動。
  - Docker は採用しない（ミニマムに対して重い）。
- **配布は単一バイナリ**を狙う（cron 的な手間を最小化）。

### 5-3. データ保持

- キュー・履歴・設定はローカル SQLite ファイルに永続化。
- 単一ユーザー想定。

### 5-4. データの整合性

- キュー内の「いま再生中」（`status='playing'`）は **キュー全体で 1 件まで**。
  DB の部分ユニークインデックスで保証する。
- 割り込みスタックは複数件あってよい（`status='paused_for_interrupt'`）。

## 6. スコープ管理（MVP の境界）

| 項目 | MVP に入れる？ | 補足 |
|---|---|---|
| URL 1 本でキューに追加 | ○ | コア体験 |
| メイン UI（プレイヤー＋キュー編集） | ○ | |
| **補助 UI（スマホ向け軽量追加 UI）** | ○ | コア体験の一部 |
| **WebSocket でのリアルタイム同期** | ○ | コア体験の一部 |
| **割り込み再生（スタック復帰）** | ○ | コア体験の一部 |
| Tier 1: YouTube IFrame Player API 再生 | ○ | oEmbed でメタ取得 |
| Tier 1: 音声直リン（.mp3 / .m4a 等）の `<audio>` 再生 | ○ | Podcast の `<enclosure>` URL もこの経路 |
| Tier 2: yt-dlp 抽出 → hls.js でアプリ内再生 | ○ | |
| Tier 3: Chrome 拡張モード | ○ | 拡張本体も MVP の成果物に含む |
| Podcast RSS の URL を貼る → エピソードを選んで追加 | △ | RSS 単発取得＋一覧 UI が要るのでサブセットでスタート |
| キューの並び替え・削除・先頭挿入 | ○ | |
| 履歴（completed/skipped）保持 | ○ | |
| 再生速度コントロール | ○ | Tier 1〜3 で動作 |
| フルスクリーン | ○ | Tier 1／Tier 2 |
| ザッピング機能（タイマー自動次へ） | × | 自動キューイングと組み合わせて意味が出る機能。MVP では作らない |
| コメントスクリーン付きフルスクリーン | × | コメント取得元未定 |
| チャンネル登録・新着 RSS クロール | × | ロードマップ |
| おすすめ／自動キュー生成 | × | ロードマップ |
| 正規表現フィルタ・ミュートリスト | × | チャンネル登録が無いと使い所が薄い |
| Radiko 連携 | × | 認証フロー実装が重い |
| 任意 UA 設定 | △ | 環境変数で 1 個だけ提供（yt-dlp と og:タグ取得に渡す） |
| スマホ対応（メイン UI） | △ | 補助 UI のみスマホ前提。メインは Windows ブラウザのみ |
| 認証 | × | LAN 限定 |

> △は「最小サブセットだけ MVP に入れる／環境変数のみで提供」の意。
