# 04. MVP 後のロードマップ

MVP（[03-mvp-design.md](./03-mvp-design.md)）を実際に運用してみて、
不便だと感じたものから順に潰していく。**事前に作り込まない**。

ここに並べた項目は「事前に作る予定」ではなく
「**作るとしたらこの形が筋が通る、という当たりだけ付けたメモ**」。

## 優先度: 高（MVP 直後に手を出しそう）

### R0. Tier 2／Tier 3 のサイト別フィージビリティ調査

MVP のコードができた段階で、自分が普段見るプラットフォームを **1 サイトずつ** 通して確認する:

- yt-dlp `-j` で `formats[]` がどう返るか（DRM の有無、HLS かプログレッシブか）。
- HLS プロキシ越しに `hls.js` で再生したときに CORS／トークン期限がどう振る舞うか。
- Tier 3 が必要なサイトでは、コンテンツスクリプトでの `<video>` 取得セレクタを記録する。

調査結果は `nagara/05-feasibility-matrix.md`（仮）に表で残す。
**MVP の DoD には含めない**（運用しながら埋めるべきもの）が、
新しいサイトを足すときの事前チェックリストとして機能する。

### R1. 「次これ見よう」を素早く積む補助 UI

MVP の核を強化する方向。
- nagara Chrome 拡張（Tier 3 用の拡張）を **「いま開いているページの URL を nagara キューへ送る」**
  ボタンも兼ねさせる（同じ拡張に機能を足すだけ）。
- 複数 URL の一括投入欄（メインの URL 投入欄を多行対応にするだけ）。
- ペースト時の自動 URL 検出（「https://...」を含む文章を貼っても URL 部分だけ拾う）。

### R2. 履歴の重複検出と "再投入抑制" の任意化

- いま `history` には残っているので、UI 側で「最近 30 日に流したやつは薄く表示」を出すだけで足りる。
- 強制的に弾くのではなく、ユーザに見せて選ばせる。

### R3. 進捗保存（途中スキップ時の `progress_seconds`）

- MVP では `skipped` の行に最終位置を入れている。
- 「続きから」UI を増やすときに、この値を読み出して `seekTo` で復元する。

### R4. キューのインポート／エクスポート

- JSON でキューと履歴を吐ける／読めるようにする。
- マシン引っ越し、別端末との同期。
- `items.source_url` の配列にしておけば再投入で復元できる。

## 優先度: 中（手動キューの運用感が見えてから）

### R5. 投稿者・チャンネル登録（自動キューイングの前段）

- ここでようやく前回の設計（チャンネル登録 + RSS クロール）に戻る。
- `channels` テーブルを足し、`items.channel_id` を NULL 許容で追加するだけで MVP 設計と互換。
- YouTube は `feeds/videos.xml?channel_id=...`、Podcast は RSS。
- 入れる粒度の判断は **手動キュー運用の中で「これは毎回貼るのが面倒だ」と感じた投稿者だけ** 登録する。
  → 「全投稿者を登録 → 全部自動」で破綻するパターンを避ける。

### R6. 自動キューイング（おすすめ／クルーズ的なやつ）

- R5 の投稿者登録と、MVP の履歴データが揃って初めて意味のある自動化ができる。
- 想定アプローチ:
  - 「明示的に登録した投稿者の新着」だけを別キュー（"オートキュー"）として持ち、
    手動キューが空になったら流す。
  - ユーザが手動キューに積んだものは常に最優先。
- ニコニコクルーズ的な「途中で続き見る？」は MVP のザッピング UI を流用する。

### R7. 正規表現フィルタ・キーワードミュート

- R5 の投稿者登録機能が入ってからでないと「フィルタ対象」がそもそも存在しない。
- `filters` テーブルを足して、自動キューイングと手動キューの両方に適用する。

### R8. Radiko 連携

- Tier 2 の枠組みに乗せる（バックエンドで auth1/auth2 → HLS → プロキシ → フロントは `hls.js`）。
- 「ながら聴き」用途と相性が良いので、需要が出たら優先度を上げる候補。

### R9. Tier 3（Chrome 拡張）の対応サイトホワイトリスト拡充

- MVP 時点で TVer 用の URL 判定ロジックは入っているが、
  運用しながら他に「ネイティブ埋め込み NG ＋ DRM ＋ 公式プレイヤーは autoplay 連鎖が効く」
  サイトを足していく。候補: AbemaTV／FOD／民放公式 VOD 群。
- 各サイトでコンテンツスクリプトの `video` セレクタが微妙に違うことがあるため、
  `extension/content/site-rules/<host>.ts` のようにサイトごとの差分を追加する形にしておく。

### R10. Chrome 拡張の Chrome Web Store 公開

- MVP では開発者モードでの読み込み運用。
- 自分以外も使うようになったら CWS 申請。プライバシーポリシー整備が要る。

### R11. コメントスクリーン付きフルスクリーン

- 取得元の問題が大きい。
  - YouTube ライブのリプレイチャットは API キー＋Quota が痛い。
  - ニコニコ過去コメントは非公式 API 利用＋規約注意。
- 描画側は `<canvas>` を Tier 1（IFrame）／Tier 2（hls.js）の player の上にかぶせるだけで素直。
- Tier 3（拡張モード）は別タブ側なので、コメントオーバーレイをかぶせるには
  コンテンツスクリプトで `<canvas>` 注入する追加実装が必要。
- データ取得の決断ができたら着手する。

## 優先度: 低（必要性が出てから）

### R12. 認証 / アクセス制御

- 自宅 LAN を出る運用が出てきたら Basic 認証または Cloudflare Tunnel 等を前置する。

### R13. スマホ対応

- レイアウトを縦長対応にすればおおむね動くはず。
- iOS Safari は `<audio>` の autoplay がさらに厳しいため、再生ボタンの導線を増やす必要がある。
- Tier 3 はモバイル Chrome では拡張未対応のため、スマホでは Tier 1／Tier 2 のみとなる。

### R14. プレイヤー Adapter の追加

- 新しいソースを足すときは `PlayerAdapter` の実装を 1 個増やすだけで済むよう、MVP で抽象化済み。
- 想定追加先: SoundCloud／Spotify Embed／Vimeo／自前 mp3 ホスティング 等。
- ほとんどは Tier 1（公式埋め込み）か Tier 2（yt-dlp）で吸収できるはず。

### R15. 統計ダッシュボード

- 「今日のうちに何時間流したか」「ジャンル比率」などを可視化。
- `history` テーブルだけで成立するので追加スキーマ不要。

## 優先度: 別軸（運用・周辺）

### R15. systemd / 自動起動の整備

- インストールスクリプト `scripts/install-systemd.sh` を整備。
- `journalctl` でログを集約。

### R16. バックアップ

- SQLite ファイル 1 個なので `cp` と `tar` で十分。
- `data/` 配下を週次でホームディレクトリの別フォルダに丸コピー。

### R17. テストとモック

- MVP では手動 E2E（自分で触って確認）で十分。
- メタ取得処理は外部 fetch があるので、ロジック関数だけ単体テストし、
  実フィードはサンプル XML/HTML をリポジトリに同梱する。

---

## やらない（明示的に除外）

- マルチユーザー化／権限制御
- リコメンドのために大きな機械学習モデルを動かす
- クラウドへのホスティング（VPS / Vercel 等）
- SaaS 化

これらは Issue の意図（「自宅で使う／自分用」）と方向が違うので、選択肢から外す。
