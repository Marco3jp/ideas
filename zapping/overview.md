# ずっと声を流し続けてくれるツール — サービス概要設計

## コンセプト

部屋にいる間、音楽でも「ちゃんと見たい動画」でもなく、**"なんとなく耳を傾けていたら意味がある"くらいの距離感**で声が流れ続けるツール。
選ぶ手間を限りなくゼロにしつつ、重複再生を極力避け、常に新鮮なコンテンツが流れ続ける状態を維持する。

---

## 想定ユーザー・利用シーン

| 項目 | 内容 |
|------|------|
| 利用者 | 個人（当面は作者自身） |
| 場所 | 自室 |
| 時間帯 | 起きている時間全般 |
| デバイス | PC ブラウザ（メインターゲット）、スマートフォンは将来対応 |

---

## 対応コンテンツソース

| ソース | 取得方法 | 備考 |
|--------|----------|------|
| YouTube チャンネル | YouTube Data API v3 | 動画・配信アーカイブ |
| Podcast (RSS) | RSS フィード | Apple Podcasts / Spotify 等で配信されているものを含む |
| Radiko | Radiko API / タイムフリー | 要認証対応（プレミアム） |
| TVer | TVer API / スクレイピング | 番組選定必要、テレ東中心 |

> **ミニマム実装**: YouTube + Podcast RSS のみ。他は段階的に追加。

---

## コア機能一覧

### 1. コンテンツ管理

- 投稿者・チャンネル・番組の登録／削除
- チャンネルごとの優先度設定（新着優先 / 古い順優先）
- エピソード単位の無効化（"まだ見ていない" 等）
- 正規表現によるタイトルマッチでの自動除外
- ミュートリスト（投稿者・動画・キーワード）

### 2. キュー管理システム

- バックエンドで再生キューを自動生成
- 視聴履歴に基づく重複排除
- チャンネルごとの順序ポリシー（新着優先 / 古い順）に従ったソート
- ザッピング機能（数分後に自動で次の動画へ遷移）
  - 続きを見るか確認する猶予画面（ニコニコクルーズ型）

### 3. 再生コントロール

- 各配信サービスの埋め込みプレイヤーを iframe でホスト
- 統一インターフェイスで以下を制御
  - ロード / 再生 / 一時停止
  - 再生速度変更
  - シーク完了（見終わり）の検知
  - フルスクリーン / コメントオーバーレイ付きフルスクリーン
- User-Agent の任意設定（リクエスト時の UA 偽装）

### 4. 視聴履歴

- 再生開始・完了を記録
- 「途中までしか見ていない」状態も保存（進捗率）
- 履歴に基づきキューへの再投入を制御

## 動作環境・ネットワーク前提

このツールはインターネットに公開しない**ローカルネットワーク専用ツール**として設計する。

| パターン | 説明 |
|---------|------|
| Linux PC で起動 → Windows PC からローカル LAN でアクセス | サーバー役の Linux PC 上で docker compose 等を起動し、同一 LAN 内の Windows PC ブラウザから `http://<linuxpc-ip>:3000` でアクセス |
| Windows PC でローカル起動 → 同 PC のブラウザでアクセス | Windows 上で直接 Node.js / docker 等を起動し `http://localhost:3000` でアクセス |

コンテンツ（YouTube 動画・Podcast 音声等）はインターネットから取得するが、**ツール自体へのアクセスはローカルネットワーク内に閉じる**。

---

## 非機能要件（初期）

- **ネットワーク閉域**: インターネット公開不要。ローカルネットワーク内からのみアクセスを想定
- **コンテンツ取得**: YouTube Data API・RSS フィード等の外部 API へのアクセスはサーバーサイドから行う（インターネット接続必須）
- **認証**: ローカル LAN 内アクセス前提のため、認証機能は MVP では省略。将来的に Basic 認証等を追加する余地は残す
- **マルチユーザー**: 当面は単一ユーザー（家族や友人と共有する場合はローカル LAN 内での共有を想定）
- **スケーラビリティ**: 個人利用なのでスモールスタートで可
- **セキュリティ**: API キーはサーバーサイドで管理。フロントに露出させない
